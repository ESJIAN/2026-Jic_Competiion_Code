## 2. 开发准备

>**背景**：这一步的背景是指的我不在且整个开发流程完全故障才需要回复到故障前的开发流程所需要执行的工作。正常对接情况下这一步可以直接跳过

1. 按照 [[D-Robots RDK 笔记#2 ) RUFUS烧录*]] 所说的做

2. 按照 [[D-Robots RDK 笔记#1.4.1. 使用串口终端配置*]] 所说的做

3. 在RDK SSH终端输入如下命令 **-->** 回车

```bash
echo "source /opt/ros/humble/setup.bash" >> ~/.bashrc
source ~/.bashrc
```

>**说明**：官方的镜像虽然部署好了 ROS2 Humble 的开发环境，但是没有给他加入到全局终端变量中

4. 在SSH终端输入如下命令 **-->** 回车

```bash
sudo apt install autocutsel -y
```

5. 在SSH终端输入如下命令 **-->** 回车

```
sudo nano ~/.vnc/xstartup
```

6. 覆盖原文加入如下命令 **-->** 保存（Ctrl+S） **-->** 退出 （Ctrl+X）

```bash
#!/bin/sh

xrdb "$HOME/.Xresources"
xsetroot -solid grey
#x-terminal-emulator -geometry 80x24+10+10 -ls -title "$VNCDESKTOP Desktop" &
#x-window-manager &
# Fix to make GNOME work
export XKL_XMODMAP_DISABLE=1
/etc/X11/Xsession 

# 启动剪切板同步
autocutsel -fork
autocutsel -selection PRIMARY -fork
```

![](https://i0.hdslb.com/bfs/openplatform/1f2dd5a19937d091f108bbd2ada5f1425070a0c1.png)

7. 在终端输入如下命令 **-->** 回车：杀死所有 VNC 实例

```bash
sudo vncserver -kill :*
```

8. 在终端输入如下命令 **-->** 回车：启动VNC，端口号为 5001

```
vncserver :1
```

>**说明**：这一步是为了 VNC 共享剪切板的，因为**TigerVNC / TightVNC / x11vnc 这类传统 VNC 默认并不支持完整的剪切板同步**，尤其是在 **RDK 开发板这种 headless + 虚拟桌面** 环境里

9. 重新连接 VNC  **-->** 随便粘贴一段内容到 VNC 客户端：如果弹窗如下所示说明你的配置成功

![](https://i0.hdslb.com/bfs/openplatform/a3d0293759204d4c96648f9ff92ceb3a30392f61.png)

>**提示**：你也可以手动输入在 SSH 终端输入 `autocutsel -fork`、`autocutsel -selection PRIMARY -fork` 两条命令手动启用 VNC 增强复制功能。

10. 按照 [[开发服务器#1. 安装]] 、[[开发服务器#2. 部署]] 所说的做（提示：如果开发服务器没有遇到重大问题可以不做）

## 5. 交接问题


- 【**问题描述**】:*VS code*在使用ssh的功能时出现以下报错,提示连接失败：
- 
```
Resolver error: Error: Failed to find a free local port for dynamic forwarding
```

- 【**问题环境**】：在进行交接时，到用*VS code*连接*RDK X5*这一步,点击*VS code*，却提示连接不上

![](https://youke1.picui.cn/s1/2025/09/23/68d2995cca19b.png)



- 【**问题分析**】：先是听取AI给的原因：*由于无可用端口*

于是采用了以下的几种解决办法

>1. 扩大端口范围

在 VS Code 设置文件(settings.json)中添加:

```
"remote.SSH.preferredLocalPortRange": {
    "start": 1024,
    "end": 65535
}
```

经过尝试，无用

>2. 禁用动态转发

在设置中添加：

```
"remote.SSH.enableDynamicForwarding": false
```

经过尝试，无用

此时一个*todesk*的图标引起了我们的注意，从这个闪烁的图标我们得到了一个重要信息，也就是网络有问题

于是我们也便开始从网络下手，以寻找问题

- 【**方案尝试**】：在决定从网络问题开刀后，我们决定重置一下网络设置

于是我们上网寻找指令

于是便找到了下面的解决方法

1. 按下Win + X键，选择*命令提示符（管理员）*。

2. 在命令提示符窗口中，输入以下命令并按*Enter*键：

```
netsh winsock reset catalog
netsh int ip reset all
```

然后重启计算机。


- 【**方案检验**】：经过检验，重置后问题得到解决

*VS code*也是如愿以偿连接到*RDK X5*了
