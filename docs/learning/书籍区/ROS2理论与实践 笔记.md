# 第1章 ROS2概述与环境搭建
## 1.1 ROS2简介

【定义】ROS（Robot Operating System）是用于构建机器人应用程序的软件开发工具包。ROS是开源的，它由一组软件 库和若干工具组成。 在机器人领域，==ROS是一个标准软件平台，这个平台为开发者提供了构建机器人应用程序所需的各个功能模块==，并 且开发者能够以==“可插拔”==的方式组织各个功能模块，无论开发者的程序是用于课堂实验、科学研究、原型设计或是最 终产品，ROS都提供了一站式的技术支持。 

>**注意**：ROS虽然字面意思是机器人操作系统，但是它并非经典意义上的操作系统，更准确的讲ROS是 一个 SDK（Software Development Kit）也即软件开发工具包。

【作用】秉着“不要重复发明轮子”的原则，通过ROS可以复用已有功能并方便快捷的拓展新功能。

### 1.1.1 ROS2发展历程

ROS2（Robot Operating System 2）作为面向机器人开发的开源框架，其发行版遵循字母顺序 + 动物命名规则，且分为长期支持版（LTS） 和短期支持版（非 LTS）。==LTS 版本支持周期长（通常 5 年），适合生产环境；非 LTS 版本支持 6-12 个月，适合开发和尝鲜==。以下从版本概述、核心区别对比、关键版本特性三个维度详细说明[^1]。

**命名规则**：按字母顺序命名，每个版本对应一种动物，以形容词+名词的格式组成（如 Ardent Apalone、Foxy Fitzroy 等）。

**支持周期**：LTS 版本支持 5 年（与 Ubuntu LTS 同步），非 LTS 版本支持 6-12 个月。

**依赖系统**：主要适配 Ubuntu（如 Ubuntu 20.04 对应 Foxy，22.04 对应 Humble），同时逐步完善对 Windows、macOS、ROS 2 for Embedded Linux（REP 2000）的支持。

**核心目标**：从早期版本的功能探索，到 LTS 版本的稳定性优化，逐步提升实时性、分布式能力、跨平台兼容性和工具链成熟度。

| 版本名称                | 发布时间    | 支持截止时间  | 对应 Ubuntu 版本       | 类型             | 核心特性亮点                                                   |
| ------------------- | ------- | ------- | ------------------ | -------------- | -------------------------------------------------------- |
| Ardent Apalone      | 2017.12 | 2018.12 | Ubuntu 16.04/18.04 | 非 LTS          | 首个正式发行版，引入 DDS 中间件、基本节点通信机制。                             |

| Dashing Diademata   | 2019.05 | 2024.05 | Ubuntu 18.04       | LTS（**STA首选**） | 首个 LTS 版本，API 初步稳定，支持 Cyclone DDS，完善导航栈（Navigation2）。    |
| Eloquent Elusor     | 2019.11 | 2020.11 | Ubuntu 18.04/20.04 | 非 LTS          | 增强实时性（支持 PREEMPT_RT），优化参数服务器（Parameters）。                |

1. 早期非 LTS 版本（探索阶段）
	
	- Ardent Apalone（2017）：ROS2 的第一个正式版本，奠定核心架构。支持基本的发布 - 订阅（Pub-Sub） 通信，依赖 DDS 中间件（默认 Fast RTPS），但 API 不稳定，工具链简陋（无成熟的colcon编译工具）。
	
	- Bouncy Bolson（2018）：完善通信模型，新增服务（Service） 和动作（Action） 机制（动作用于长周期任务，如导航路径跟踪）。首次全面支持 Python 3，逐步替代 Python 2。
	
	- Crystal Clemmys（2018）：优化开发工具链，引入ament_cmake构建系统（替代传统 CMake），提升跨包依赖管理效率。开始支持 Windows 平台，但兼容性有限。

2. 首个 LTS 版本：Dashing Diademata（2019），作为 ROS2 的第一个长期支持版，Dashing 标志着框架从 “实验” 走向 “可用”
	
	- API 初步稳定：核心接口（如rclcpp/rclpy）基本固定，减少后续版本的破坏性更新。
		
	- 导航栈起步：Navigation2 包首次在 ROS2 中稳定运行，支持机器人路径规划、避障等基础功能。
		
	- DDS 多样化：除默认 Fast RTPS 外，新增对 Cyclone DDS 的支持（轻量级，适合嵌入式）。
		
	- 局限性：实时性能较弱，无加密通信支持，工具链（如ros2cli）功能简单。
	

3. 成熟 LTS 版本：Foxy Fitzroy（2020），Foxy 是 ROS2 的里程碑版本，被工业界广泛采用：
	
	- API 完全稳定：核心库（rcl、rmw）接口冻结，后续版本兼容此 API，降低升级成本。
		
	- 默认 DDS 优化：将 Cyclone DDS 设为默认（替代 Fast RTPS），提升低资源设备兼容性。
		
	- 工具链完善：colcon编译工具成熟，ros2cli支持节点列表、话题查看、参数修改等实用功能。
		
	- 跨平台增强：完善 Windows 10 和 macOS 支持，可在非 Ubuntu 系统中稳定运行。

4. 最新 LTS 版本：Humble Hawksbill（2022），Humble 是当前生产环境的首选版本，支持至 2027 年：
	
	- 语言与系统升级：支持 C++17（提升代码效率）和 Python 3.10，适配 Ubuntu 22.04（长期支持至 2032 年）。
	
	- 实时性能优化：通过ros2_realtime包增强对 PREEMPT_RT 内核的支持，满足机器人实时控制需求（如机械臂关节控制）。
	
	- 安全性增强：支持 DDS-Security（加密通信、身份认证），适合多机器人协作或敏感场景。
	
	- 生态扩展：集成更多成熟功能包（如 SLAM Toolbox、MoveIt 2），降低开发门槛。

5. 近期非 LTS 版本（功能迭代）
	
	- Galactic Geochelone（2021）：引入组件节点（Component Nodes），支持动态加载 / 卸载节点，提升模块化能力；优化分布式通信的 QoS（服务质量）配置。
		
	- Iron Irwini（2023）：完善生命周期节点（Lifecycle Nodes），支持节点状态管理（如 “未配置 - 活跃 - 关闭” 状态切换）；增强调试工具ros2 doctor，可自动检测系统依赖和配置问题。
		
	- Jazzy Jalisco（2024）：紧跟技术趋势，支持 C++20 和 Python 3.12；默认 DDS 切换为 Fast DDS（性能更强）；新增 AI/ML 集成工具，支持 TensorRT 加速推理，适配机器人视觉和决策场景。

>**注意**：官方于2020年发布了ROS1的最终版本，并将于2025年终止ROS1的维护。而早在2017年就 已经推出了ROS2的第一个正式版本，并且随着ROS2的不断完善，于2022年又推出ROS2的 第一个5年长支持版。对于ROS而言，这是一个里程碑式的事件，这意味着自此开始，ROS2将 全面取代ROS1。

```ad-note
title:版本选择建议

生产环境：优先选择 LTS 版本（如 Humble Hawksbill），支持周期长、稳定性高，且社区文档和问题解决方案丰富。

系统适配：需与 Ubuntu 版本匹配（如 Ubuntu 20.04 选 Foxy，22.04 选 Humble，24.04 选 Jazzy），减少兼容性问题。

迁移成本：从旧版本升级时，需关注 API 变化（如 Foxy 到 Humble 无破坏性更新，可平滑迁移；但早期版本升级可能需修改代码）。

开发验证：若需尝鲜新功能（如 AI 集成、动态节点），可选择最新非 LTS 版本（如 Jazzy Jalisco），但需注意支持周期，避免项目中期版本过期。

```

### 1.1.3 ROS2优势

#### (1) 与其他软件框架比较

|优势方面|具体描述|
|---|---|
|**开源与免费**|ROS一直是开源的，并且将永远是开源的，确保全球开发者可以自由、不受限制地访问高质量、功能齐全的机器人SDK。同时官方鼓励开源贡献，也不反对将ROS集成进专有产品。|
|**多平台支持**|ROS2支持Linux、Windows、macOS以及各种嵌入式平台（通过micro-ROS），并且不同平台都通过了官方测试，实现了开发与部署的无缝衔接。分层支持模型还允许将ROS2移植到实时和嵌入式操作系统等新平台上。|
|**应用领域广泛**|ROS可以在各种机器人应用中使用，从室内到室外，从家用到汽车，从水下到太空，从消费市场到工业领域，ROS都可以独当一面。|
|**全球化社区**|十多年来，ROS项目通过培育由数百万开发人员和用户组成的全球化社区，为机器人技术做出贡献和改进，从而产生了一个庞大的机器人软件生态系统。|
|**缩短产品上市时间**|ROS提供了开发机器人应用程序所需的工具、库和功能，使开发者可以将更多的时间花费在与自身业务相关的工作上。由于它是开源的，开发者可以决定何时何处使用ROS，甚至还可以根据自身需求修改ROS。|
|**广泛的行业支持**|业界对ROS的支持非常强大。除了在ROS上开发产品外，来自世界各地的大大小小的公司都在投入资源为ROS做出开源贡献。|
|**业界肯定**|整个机器人行业都依赖于ROS。ROS是教授机器人技术的标准，是大多数机器人研究的基础，从单个学生项目到多机构合作再到大型竞赛，ROS都占据着主导地位。世界各地不计其数的机器人内部都运行着ROS。|

#### (2) 对比 ROS 1 的优势

![](https://i0.hdslb.com/bfs/openplatform/ed681f37faa130655974f97f4bbdf4ebf11fe121.png)


<center><b>表：ROS 2 相较于 ROS 1 的优势对比</b></center>

|对比维度|ROS 1|ROS 2|优势说明|
|---|---|---|---|
|**系统架构**|集中式架构，依赖 `roscore` 中央主节点|去中心化架构，基于 DDS (Data Distribution Service)，无单点故障|去除单点故障，`roscore` 崩溃不会导致整个系统瘫痪，系统稳定性更高。|
|**通信机制**|自定义 TCPROS/UDPROS 协议|采用工业标准 DDS 作为通信中间件|通信更可靠，支持多种传输方式（UDP、TCP、共享内存），并能自动选择最优传输。|
|**实时性能**|实时性较差，通信延迟较高（100节点时>50ms）|实时性显著提升，通信延迟低（1000节点时<5ms），支持软实时和硬实时|更适合工业自动化、自动驾驶等对实时性要求高的场景。|
|**QoS 支持**|缺乏完善的 QoS 机制|提供丰富的 QoS (服务质量) 策略（22种），如可靠性、截止时间、历史数据等|能保证复杂网络环境下的通信质量，避免数据丢失，适合高速系统。|
|**平台支持**|主要支持 Linux|支持多平台：Linux, Windows, macOS, 实时操作系统 (RTOS)|开发环境选择更灵活，便于跨平台开发和部署。|
|**网络环境适应性**|对网络质量要求高，跨网络通信能力弱|更好的网络容错性，支持分布式多机器人系统，适应复杂网络条件（如无线、移动网络）|更适合多机器人协作、车联网 (V2X) 等分布式应用。|
|**安全特性**|安全性较弱|支持 DDS-Security，提供加密、认证和访问控制|满足工业级、航空航天、国防等领域的安全需求。|
|**节点发现**|依赖 `roscore`，节点发现慢（100节点>120秒）|去中心化动态发现（SPDP/SEDP协议），节点发现快（1000节点<8秒）|系统启动和节点发现更迅速，更适合大规模系统。|
|**进程内通信**|支持有限|支持高效的 intra-process 通信（零拷贝），减少内存复制和系统开销|提升同一进程内多个节点间的通信效率，节省资源。|
|**应用场景**|更适合教育、研究、小规模原型开发|更适合工业自动化、自动驾驶、航空航天、多机器人系统等产品级应用|ROS 2 的设计更贴近产品化和工业化需求。|

>**总结**：ROS 2 并非仅仅是 ROS 1 的升级版，而是在**架构理念**、**通信机制**、**性能表现**和**适用性**上进行了全面革新。它通过采用**去中心化的 DDS 中间件**、**丰富的 QoS 策略**、**跨平台支持**以及**增强的安全特性**，有效解决了 ROS 1 在大型项目、实时系统、分布式部署和产品化应用中遇到的诸多瓶颈。

>**提示**：对于**新项目**，尤其是涉及**工业应用**、**自动驾驶**、**多机器人协作**或对**实时性及可靠性**有较高要求的场景，**强烈建议直接采用 ROS 2**。对于已有的 ROS 1 项目，ROS 2 也提供了 `ros_bridge` 等工具进行兼容或迁移。
