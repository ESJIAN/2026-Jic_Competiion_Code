### 🔴 问题 2: Lidar 节点启动时报错 `RPLidar` 未定义
- 【**问题描述**】：当运行 `src/execution/lidar_control/lidar_control/lidar_node.py` 且代码进入 `while self.running and rclpy.ok(): if self.use_mock or RPLidar is None:` 分支判断时，若未导入 `RPLidar`，会直接抛出 `NameError`。最小复现 MVP：在未安装 `rplidar` 依赖、且文件中没有 `RPLidar` 定义时启动节点。
- 【**问题环境**】：软件：Python 3 + ROS 2（rclpy）+ Linux；硬件：激光雷达节点运行主机。
- 【**问题分析**】：核心原因是符号引用早于定义。业务逻辑允许“库缺失时退化到 mock/非 RPLidar 路径”，但导入层没有提供兜底变量，导致分支判断本身先失败。
- 【**问题状态**】：✅ 已解决
- 【**问题方案**】：在导入区增加可选导入与兜底定义，确保 `RPLidar`/`RPLidarException` 在任何环境下都可被安全引用。

```code
try:
    from rplidar import RPLidar, RPLidarException
except ImportError:
    RPLidar = None

    class RPLidarException(Exception):
        pass
```

> 【代码解读】当 `rplidar` 包存在时走真实驱动；不存在时显式把 `RPLidar` 置为 `None`，让主循环中的 `self.use_mock or RPLidar is None` 判定成立并进入兼容路径，同时异常捕获类型仍合法，避免二次 `NameError`。

- 【**知识总结**】：这次问题的核心原因是“可选依赖”只在业务分支考虑了降级，却没有在“符号定义层”做好兜底。通过这次修改，我学到了对于可选第三方库，必须先保证名称总是可解析，再谈运行时分支降级。
- 【**编码建议**】：建议下次遇到类似问题时，可以先检查“所有在条件判断和异常捕获里出现的符号是否在导入失败场景下仍有默认定义”；这类 Bug 通常与可选依赖处理不完整相关。
